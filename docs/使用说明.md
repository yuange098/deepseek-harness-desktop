# DeepSeek Harness 本机安装说明

安装日期：2026-09-24 · 安装位置：`E:\DeepSeekHarness`

## 一、怎么用（每天只需要这一步）

双击桌面上的 **DeepSeek Harness** 快捷方式（开始菜单里也有）。

程序会自动做三件事：启动本地 dsh 服务 → 等它就绪 → 在独立窗口里打开界面。你不再需要打开浏览器、也不需要敲命令。启动时会出现一个过渡小窗，首次约 20–40 秒，之后一般 10 秒左右。

关掉窗口不会退出程序，它会缩到右下角托盘继续跑（长任务不会中断）。真正退出用托盘右键 → **退出**。

## 二、第一次要做的两件事

1. **填 API Key**：界面里打开 **设置 → 模型**，粘贴你的 [DeepSeek API Key](https://platform.deepseek.com/) 并保存。不填 key 就只能看界面、不能干活。
2. **选工作区**：点左侧 **工作区 → 添加**，选你要让 AI 干活的项目目录。默认工作区已经指向 `E:\DeepSeekHarness\workspace`。

## 三、目录结构

| 路径 | 用途 |
| --- | --- |
| `desktop\dist\DeepSeek Harness-win32-x64\DeepSeek Harness.exe` | 桌面客户端本体 |

| `home` | DSH_HOME：profile、插件、会话记录、设置 |

（以上都在 `E:\DeepSeekHarness\` 下。）

### 怎么删除一个对话（删了不能恢复）

1. 鼠标移到左侧**工作区列表里的某个对话**上，行尾会出现几个小按钮，最右边那个是**垃圾桶**（和官方的"…"菜单、新建会话按钮并排）。
2. 点垃圾桶 → 弹出确认框：写明「删除后**无法恢复**」，并列出会被清掉的内容（消息与轨迹、代码归档、本地缓存）。
   弹窗里还会先显示这个对话的**规模**：轮次、步骤、磁盘占用、输出 tokens，删之前心里有数。
3. 点「永久删除」才算删；点「取消」或按 Esc 什么都没发生。删完页面会自动刷新，列表里就没有它了。

几点要知道的：

- 官方的客户端接口**没有**删除会话这个动作，所以删除是在**桌面版**里由程序直接清理本机数据；如果你是在浏览器里打开 DSH，点「永久删除」会提示你改用桌面版。
- 删除范围：`home/sessions/<工作区>/<会话id>/`（对话记录本体）、`home/storages/session_projcache/sessions/<id>.json`（投影缓存），以及 `home/storages/workspace.json` 里的登记。
- **不会**动 `home/attachments/` 里的附件对象：那是所有对话共用的内容寻址存储，删单个对话时不动它，免得连带别的对话的附件一起没。
- 空白的「新会话」行没有垃圾桶按钮（官方对空白会话本来就不给行内操作）。
- 如果你删的**正是当前打开的那个对话**，删除后列表里可能还会残留一条（服务端内存里还留着它），**重启一次软件**就会清掉——磁盘上的记录当时就已经删了，弹窗里也会提示这一点。

刻意**没有**装的（版本不兼容被 DSH 自己的兼容检查拒绝，或功能重复）：

- `@nanmicoder/dsh-agent-teams`（多智能体）——只支持 DSH 0.1.5-rc.1，本机是 0.1.7-rc.2；DSH 内核已自带 subagent / agent-team / workflow 能力。
- `@yejiming/dsh-data-agent`（数据库 SQL）——精确钉死 0.1.7-rc.1，与本机 rc.2 差一个版本，被拒。
- `@anionex/dsh-turn-rewind`（会话回退）——装上后激活失败（缺 `settingsScope` 服务），已移除。
- 其余视觉 / 搜索 / 主题 / 通知类插件——与已装的重复。

### 关于界面外观

当前生效的是自建的 **Harness 官网风格主题**（`dsh-harness-site`），**全部为不透明配色**，靠明暗层次区分区域：

| 层级 | 部位 | 浅色 | 深色 |
| --- | --- | --- | --- |
| 外壳 | 画布 / 主框架 | `#F9F8F8` | `#0F0F0F` |
| 外壳 | 侧栏（导航 / 工作区列表） | `#FFFFFF` | `#151515` |
| 内容面 | 次级面板、卡片、输入区、气泡 | `#FFFFFF` / `#F4F2EF` | `#1A1A1A` / `#1E1E1E` / `#222222` |
| 浮层 | 设置等弹窗、菜单、提示 | `#FFFFFF` | `#202020` / `#303136` |

**关于"玻璃/透明界面"：已按稳定性要求撤回**（2026-09-25）。当时试过「透明窗口 + Windows 11 acrylic 材质 + 半透明面板」的真玻璃方案，实测在 Windows 上有四个无法绕开的问题：

1. 透明窗口会让**原生标题栏的最小化/最大化/关闭按钮失效**（Electron 在 Windows 上的已知限制，`maximizable` 会被系统强制判为 false）；
2. 透明窗口的**边框不能拖拽缩放**；
3. 透明窗口要等 DWM 合成首帧，**窗口出现明显变慢**；
4. 打开开始菜单/托盘菜单时，Windows 会主动**关掉 acrylic 模糊**，导致界面局部变暗（系统行为，无法配置）。

因此现在回到不透明窗口：原生按钮、拖拽缩放、即时出现全部正常。如果以后 Windows/Electron 修好了这些限制，可以按记录再打开——相关配置在 `desktop\src\main.js` 的 `ensureMainWindow()`（当时是 `transparent: true` + `backgroundMaterial: 'acrylic'`），主题里的 alpha 值也只需改回小数即可。

窗口行为补充说明：

- **启动方式**（2026-09-25 按你的要求定制）：点击图标后，屏幕正中浮出一个**透明启动窗**——没有矩形底板、没有文字，只有：
  - **黑鲸鱼标记**（172px，比之前大；原来的白色底板已去掉，透出背后桌面/窗口），带一层柔和投影保证在任何壁纸上都看得清；
  - 下方一条 **216×7 的圆角进度条**（品牌蓝 → 青色渐变，底槽半透明），随启动阶段推进：开始输出日志 → 45%，服务给出地址 → 80%，界面绘制完成 → 100% 后自动关闭并显示主界面。
  - 整个启动窗可以拖动（按住图标即可），置顶显示、不占用任务栏。
  衔接方式（避免两个窗口同时出现）：主界面先在后台把首帧渲染好 → 进度条走满（100%）→ 启动窗淡出消失 → 主窗口才显示，所以是从启动窗"无缝"切到已经画好的主界面，不会出现启动窗还在、主界面已经冒出来的重叠。
  实测时间线：0.1s 无窗口 → **0.7s 只有启动窗** → **5.7s 只有主界面**，逐 100ms 采样期间从未出现两者同时可见。
- **尺寸兜底**：启动时会读取上次的窗口位置并**按显示器工作区裁剪**，避免出现"窗口比屏幕还大、按钮跑到屏幕外"的情况。若还是觉得窗口位置不对，删掉 `home\desktop-window-state.json` 再启动即可恢复默认尺寸。
- 标题栏/菜单栏是系统原生控件，跟随 Windows 的"应用模式"（当前浅色）；想让这条也变深，把 Windows 设置 → 个性化 → 颜色 → 应用模式改为"深色"。

## 六、常见问题

- **窗口没出现**：看右下角托盘图标（可能在折叠区），双击唤出；或从开始菜单再点一次。
- **卡在启动界面**：打开 `E:\DeepSeekHarness\logs` 里最新的日志看最后几行，或用菜单 **文件 → 打开日志文件夹**。
- **端口占用 / "DSH 服务已退出（code=1）"**：已修复（2026-09-25）。当时的问题是：启动过程中若再次双击图标，会**重复走一遍启动流程**，第二个服务抢不到 3080 端口就报 `startup failed` 并退出，而它又没被跟踪，导致后面重启时端口漂到 3081、系统里同时留着一个孤儿服务。现在客户端做了三层防护：
  1. **启动防抖**：同一时间只允许一个启动流程；启动中再次点图标只把启动窗提到前面，不会重新启动。
  2. **启动前清理残留**：每次启动服务前，先扫一遍并结束"上次遗留的、跑本安装目录 dsh 的 node 进程"，保证端口从 3080 开始且只有一个实例。
  3. **重启串行化**：点"重启本地服务"时会先等上一次启动收尾，两套流程不会互相踩。
  实测：连点两次图标后，服务进程数保持 1 个、端口稳定 3080，日志无 startup failed。
- **升级 DSH 本体**：
  ```powershell
  npm install -g --prefix E:\DeepSeekHarness\core @deepseek-ai/dsh@<版本>
  ```
  升级后建议在插件市场里「全部更新」一次。
- **彻底卸载**：删掉 `E:\DeepSeekHarness` 整个目录 + 桌面 / 开始菜单快捷方式即可。所有数据都在这个目录里，不会散落到系统其他地方。

### 界面微调（2026-09-25 按需求加的）

| 需求 | 实现方式 | 实测 |
| --- | --- | --- |
| 侧栏底部「上下文洞察 / 设置」并排，且前者改名「洞察」 | 主题插件注入 CSS（`.hHd-Xa_footArea` 改 row）+ MutationObserver 改写标签文本 | 两入口 x=12 / x=144 同一行；标签显示"洞察" |

| 右栏 7 个入口按钮尺寸 | 按实测结构定位行元素（`_entryCell` > `div(contents)` > 行），只改"行"本身：宽 380→**253**（按需求缩小 1/3）、高 →**50**、内边距 6/12、圆角 12、行距 8、图标 20、字号 13.5；行内再套按钮的插件卡片（新建终端）让内层按钮跟随行宽高 | 实测 7 行 253×50，标签与快捷键提示都不溢出 ✓ |
| 聊天框两侧的「拖动改宽度」手柄太容易误触 | 官方 `dsh-client-ui-conversation` 在聊天列左右各放了一条 `widthHandle`（10px 宽、整列高、`cursor:col-resize`），鼠标扫过就能把聊天列拖宽拖窄；主题插件注入 CSS 只隐藏这两条手柄，不动容器与布局，右侧面板那根把手保留 | 手柄尺寸变 0×0（碰不到），右侧面板把手仍在 ✓ |
| **侧栏容器随按钮自动适应** | 宽度是 app 自己的布局状态（面板上的 `--dsh-sidebar-width`、占位列 `rightbarCol`、把手位置都由它算），**不能硬写内联宽度**（会被重渲染覆盖、还会在纵向 flex 上把高度压成方块）。做法：① 量出按钮宽 + 内外边距 = 容器该有的宽度；② 把这个"是按多宽的按钮算的"记进 `panel-hug-base`；③ 对把手发 pointer 事件**替用户拖一次**，让 app 自己把列/面板/内容层/把手一起算对。按钮宽度一变（改样式/官方升级）就自动重算；按钮没变时你手拖的宽度说了算 | 实测：按钮 380 → 容器 410；按钮改成 253 → 容器自动 300（app 最小宽度，收不动为止）；按钮改 320 → 容器自动 350；手拖到 520 不被拉回且被记住 ✓ |
| 右栏收起状态启动时样式不生效 | 面板 DOM 是用户点开侧栏才挂载的，原来只在启动后 4 秒内试三次 → 补 MutationObserver，面板一出现就装样式 | 冷启动 → 点开侧栏 → 卡片仍是 380×36、内边距 6/8 ✓ |

想调整：改 `plugins\dsh-harness-site\lib\client.js` 里的 `installUiTweaks()`（面板宽度、描边颜色、并排顺序都在那几行）。

菜单栏 **帮助 → 检查更新…**（托盘右键菜单里也有同一个入口）：

- 会去 npm 官方 registry 查两件事：**Harness 核心**当前版本 vs 最新发布版本；**已装插件**逐个对比最新版。
- 弹窗列出「哪一项可更新 / 已是最新」；存在更新时还会给出可直接粘贴执行的命令，并支持一键**复制更新命令**到剪贴板。
- 它**只检查、不改动任何文件**；真正的升级动作由你自己执行。
- 检查结果会同时落一份 JSON 到 `logs\update-check.json`。

命令行方式（软件打不开时也能用，或在脚本里调用）：

```powershell
& "E:\DeepSeekHarness\desktop\dist\DeepSeek Harness-win32-x64\DeepSeek Harness.exe" --check-updates
```

升级命令（弹窗里会自动生成，长期有效）：

```powershell
# 升级 Harness 核心（把 <版本> 换成检查结果里的版本）
npm install -g --prefix E:\DeepSeekHarness\core @deepseek-ai/dsh@<版本>

# 升级全部插件（也可以直接在 设置 → 插件市场 里一键更新）
E:\DeepSeekHarness\dsh.cmd plugin --profile web update
```

## 八、关于"DeepSeek 更新模型"

模型更新和软件更新是两条独立的线：

- **新模型**：去 **设置 → 模型**，在 provider 那一行点 **「获取可用模型」**——DSH 会直接询问 DeepSeek 官方 API 当前提供哪些模型，返回候选列表，勾选即可加入，**不需要等 harness 出新版**。
- **同名模型换代**（例如 `deepseek-flash` 背后升级到新版本）：什么都不用做，你本来就在用最新的。
- 内置默认模型清单（`deepseek-flash` / `deepseek-v4-pro`）只是默认值，模型列表是配置项，可以自己增删（id、显示名、上下文长度、是否支持图片）。

## 九、安全提醒

插件是第三方代码，权限和你本人相同（能读文件、用凭据、联网）。已装插件都来自榜单收录项目，但「收录」不等于安全审计。不熟悉的插件建议先在没密钥的环境里试。
