## 一、DSH 插件的加载机制

一个插件要生效，必须同时满足三件事：

1. **装到 profile 的 `dependencies` 里**（`E:\DeepSeekHarness\home\profiles\web\package.json`）。用 `link:E:/DeepSeekHarness/plugins/<名字>` 装，改源码即时生效，不用重装。
2. **在 `dsh.profile.bundles` 数组里挂载**。只写 dependencies 不写 bundles 是不会被加载的——这是最容易漏的一步。
3. 插件自己的 `package.json` 里声明好入口：

```jsonc
{
  "main": "lib/index.js",                     // 服务端（Node 侧）入口
  "exports": {
    ".":        { "default": "./lib/index.js" },
    "./client": { "default": "./lib/client.js" },   // 浏览器侧入口
    "./package.json": "./package.json"
  },
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": {
      "inject": ["@deepseek-ai/dsh-client-ui-theme"],  // 依赖的官方包，必须在 inject 里声明
      "platform": "web",
      "immediately": true
    }
  },
  "peerDependencies": { "react": "^18.3.1" }        // 必须写，否则白屏
}
```

### 两条硬规则

- **`react` 必须进 `peerDependencies`**：插件里的 hooks 如果拿到的是另一份 React 实例，页面会直接白屏。
- **用到哪个官方上下文，就在 `inject` 里写哪个**：例如访问 `ctx.uiConversation` 而不声明，会报 `cannot get property "uiConversation" without inject`。

## 二、`dsh-harness-site`（主题 + 界面微调）

### 2.1 配色：用 token 覆盖，而不是改官方 CSS

插件通过 `ctx.theme.overrideTokens("dsh-harness-site", TOKENS)` 给出深浅两套值，官方组件自己会去读这些变量，所以升级官方版本时不容易崩。

| 用途 | 浅色 | 深色 |
| --- | --- | --- |
| 画布 | `#f9f8f8` | `#0a0a0a` |
| 主按钮 | `#1a1615`（近黑） | `#ffffff` |
| 品牌链接 | `#4d6bfe` | `#6799fe` |
| 侧栏 / 卡片 | `#FFFFFF` / `#F4F2EF` | `#151515` / `#1E1E1E` / `#222222` |
| 自己发的消息气泡 | `#E8F0FE` + 蓝边 | 同左（描边 `rgba(77,107,254,.35)`） |

### 2.2 运行时 CSS：只做 token 覆盖不到的事

| 目标 | 做法 |
| --- | --- |
| 右栏 7 个入口按钮尺寸 | 按实测层级定位行元素（`entryCell > div(display:contents) > 行`），把行改成 **253×50**、内边距 `6px 12px`、圆角 `12px`；行内再套按钮的插件卡片（「新建终端」）让内层按钮跟随 |
| 右栏内容贴边 | 面板内容层左右内边距 6px、列表内边距 8px |
| 侧栏底部并排 | `footArea` 改 `flex-direction: row`，两个入口各占一半 |
| 名字太长 | 轮询把「上下文洞察」改写成「洞察」 |

### 2.3 面板宽度的全局记忆

官方把布局宽度**按会话**存（`dsh.sidebar-right.v1.<会话id>`），换个会话就回默认值。插件做了两层：

1. **记住**：挂钩 `Storage.prototype.setItem`，官方落盘时顺手把宽度抄到全局键 `dsh-harness-site:panel-width`；再挂 `ResizeObserver` 兜底捕获拖拽结果（600ms 防抖）。
2. **恢复**：面板挂载时，如果当前宽度和全局值不一致，就"替用户拖一次"（见下）。

### 2.4 容器跟着按钮走（本仓库最绕的一段）

**为什么不能直接写宽度**：侧栏宽度是 app 自己的布局状态——面板上写着 `--dsh-sidebar-width`，占位列 `rightbarCol` 和拖拽把手的位置都由它推导。硬写内联宽度有三个后果：被下一次渲染覆盖；面板表面与内容层宽度不一致 → 右侧留一条空白；面板内容层的父级是**纵向 flex**，写 `flex-basis` 等于写高度 → 内容被压成正方形。

**做法（三步）**：

```js
// 1) 量：按钮宽 + 面板内边距(6×2) + 列表内边距(8×2) + 滚动条 + 2
const target = card + 6 * 2 + 8 * 2 + chrome + 2;

// 2) 记：这个宽度是按多宽的按钮算出来的
localStorage.setItem("dsh-harness-site:panel-hug-base", String(card));

// 3) 拖：对右侧把手派发 pointer 事件，让 app 自己把整条布局算对
handle.dispatchEvent(pointer("pointerdown", startX, 1));
for (…) handle.dispatchEvent(pointer("pointermove", x, 1));   // 必须发给把手本身
handle.dispatchEvent(pointer("pointerup", endX, 0));
```

**三个坑**：

- 事件必须发给**把手本身**（还要带 `mouse*` 事件兜底）。只发给 `document` 时，实测 app 只吃掉第一步位移。
- `pointerId` 用 `1`；用别的 id 时 app 不响应。
- 目标宽度要**在内存里也存一份**（`hugTarget`）。存储里的值随时会被 app 自己的 `ResizeObserver` 用旧宽度盖掉，只靠存储会出现"该收窄却没动"。

**不抢用户方向盘**：监听 `pointerdown / mousedown / touchstart` 记时间戳，2 秒内不做任何自动收窄；按钮宽度没变（`panel-hug-base` 一致）时也完全不插手。

## 三、`dsh-code-history`（「代码」页签）

### 3.1 挂载方式

注入到会话视图的 `conversation.view` 槽位：`id=code`、`order=30`、`label="代码"`，排在「对话 / 轨迹 / 上下文」之后。

### 3.2 数据从哪来

| 来源 | 内容 |
| --- | --- |
| `useTrajectory` | 轨迹事件：`eventNodes[].blocks[]`，块有 `kind` / `text` / `turn` / `time`（软件自己执行时的动作与产物） |
| `useChat` | 消息：`nodes`（**是 `Map`，不是数组**）、`order` |
| `useConversation` | 当前视图集合（用来判断在哪个页签） |

提取时**跳过**这些键，否则会卡：`reasoning` `thinking` `image` `base64` `snapshot` `diff` `patch` `stdout` `stderr` `output` `trace`；递归深度限制在 5~6 层。

只收两类东西：**文件写入**（软件执行时真正落盘的代码）和**回答里的代码块**；多行内联脚本（heredoc ≥ 3 行）也收，普通一行命令不收（那是命令，不是模块）。

### 3.3 分类与标题

- **执行**：轨迹里软件自己写下的代码（如"帮我按数据画山脊图，它自己写的脚本"）。
- **回答**：直接回答我提问时给出的代码（如"给我画山脊图的代码"）。
- 标题用 20+ 条中文规则推断意图（气泡图、数据清洗、可视化、爬取…）。规则命中不了就退回"代码片段 + 序号"。标题**可双击改名**，失焦自动保存，另有「恢复」。

### 3.4 卡片上放什么

除标题外还展示：语言、依赖 chips、「输入 → 输出」流程条、运行状态（✅ / ❌ / ⚠️）、智能预览（挑有信息量的行，而不是简单取前两行）。卡片支持整体/选择性复制、导出 Markdown、搜索、定位到原对话、查看修改轨迹、合并成可运行版本（import 去重 + 同名 `def/class` 取最后一次）。

### 3.5 性能

第一版在长会话里会卡（点一下代码页签要等很久）。原因与处理：

| 问题 | 处理 |
| --- | --- |
| 订阅了整个快照对象，任何变化都触发重渲染 | 只订阅原始类型（消息数、轨迹长度等） |
| 每次变更都重算 | 500ms 防抖 |
| reasoning / thinking 文本很大 | 提取时整段跳过 |

## 四、`dsh-session-tools`（删除对话）

### 4.1 为什么不能"在客户端里删"

官方客户端的 session 接口只有：`attachment / cancel / canOpenWorkspacePath / control / create /
follow / fork / initializeDefaultModel / list / modelCatalog / openWorkspacePath / page /
projections / prompt / rename / search / selectModel / updateQueue / workspacePathApplications`
—— **没有 delete**。workspace 侧只有 `workspace/delete`（删整个工作区）。

所以「删掉某个对话」只能落到文件系统，而页面没有这个权限 → 交给桌面壳。

### 4.2 一个会话的数据在哪

| 位置 | 内容 |
| --- | --- |
| `$DSH_HOME/sessions/<工作区目录>/<session-id>/session.v4.jsonl.zstd` | 对话记录本体（压缩的 jsonl） |
| `$DSH_HOME/storages/session_projcache/sessions/<session-id>.json` | 投影缓存（列表/标题等派生态） |
| `$DSH_HOME/storages/workspace.json` | 工作区登记表，`tables.workspaces[*].sessionIds` 里写着这个会话 |
| `$DSH_HOME/attachments/v1/objects/**` | **共享**附件库（内容寻址），没有"哪个会话在用"的映射 → 删单个会话时不动它 |

### 4.3 实现

```
会话行垃圾桶按钮（插件 client 半边）
   ↓ window.dshDesktop.deleteSession(id)   ← preload 用 contextBridge 暴露的唯一口子
   ↓ ipcMain.handle('dsh:delete-session')  ← 桌面壳主进程
session-store.js: 校验 id → 算目标 → 删目录/文件 → 从 workspace.json 摘登记
   ↓
页面 reload，列表刷新
```

**安全点**（都在 `session-store.js` 里）：

1. `sessionId` 必须匹配 `^(session-)?<uuid>$`，其它一律拒绝 —— 防止 `../` 之类穿越。
2. 每个删除目标都要 `path.relative` 检查确实落在允许的根目录里，且 basename 等于目标名。
3. `workspace.json` 用"临时文件 + rename"原子写，写坏了也不会留半个文件。
4. 删除逻辑与 Electron 解耦（纯 Node 模块），可以直接跑单元测试：

```powershell
node tools\publish\test-session-store.js   # 9 项：列清单/真删/摘登记/拒绝穿越/不动其它会话
```

## 五、桌面壳（`desktop/`）

### 5.1 启动时序

| 时刻 | 发生什么 |
| --- | --- |
| 0 | 显示启动窗（无边框、透明底、居中，只有图标 + 进度条） |
| 0.45 | `dsh web` 开始输出日志 → 进度条 45% |
| 0.8 | 服务打印出访问地址 → 进度条 80% |
| 服务就绪 | 主窗口在**隐藏状态**下加载 URL，并靠 `paintWhenInitiallyHidden: true` 先把首帧画好 |
| 首帧就绪 (`ready-to-show`) | 短暂延迟后 `mainWindow.show()`，同时启动窗 170ms 淡出并销毁 → 观感上是"启动画面直接变成主界面" |

### 5.2 其它实现点

| 能力 | 实现 |
| --- | --- |
| 端口占用 | `getFreePort(3080)` 从配置端口开始试，占用就 +1 |
| 单实例 | `app.requestSingleInstanceLock()`，第二次启动时唤醒已有窗口 |
| 启动免疫 | 启动后 15 秒内如果窗口被"非用户操作"最小化，会自动还原（自动化会话里启动时遇到过） |
| 关窗 ≠ 退出 | `close` 事件改为 `hide()` 到托盘，并首次弹气泡提示；真正的退出在托盘菜单 |
| 残留清理 | 启动前 `taskkill /pid <旧pid> /T /F` 清掉上次的服务进程 |
| 右键菜单 | 主进程拼 `Menu`：选中文字 → 复制/纯文本/全选；输入框 → 剪切/复制/粘贴；图片 → 复制图片；链接 → 打开/复制 |
| 检查更新 | 读本地已装版本 → 查 npm registry → 弹窗只做提示，可一键复制升级命令（也支持 `--check-updates` 命令行） |
| 窗口状态 | 位置 / 尺寸 / 是否最大化存 `desktop-window-state.json` |

### 5.3 打包与同步

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1     # 复制 Electron 运行时 + rcedit 打图标
npm run package                                          # 或者 electron-packager
```

**改完 `desktop/src/main.js` 一定要同步到打包产物的 `resources\app\src\`**，否则双击 exe 跑的还是旧代码（这个坑踩过）。

另外 `build.ps1` 内的注释是**故意只用 ASCII** 的：Windows PowerShell 5.1 会把无 BOM 的脚本按 ANSI 读，中文会乱码甚至语法错误。

## 六、调试与验收方法

这套界面大量依赖官方内部 DOM，改之前**先取证**比反复试错快得多：

| 手段 | 说明 |
| --- | --- |
| 独立 Electron 实例 + `executeJavaScript` | 用仓库同款 Electron 打开真实页面，直接读 DOM 的类名、尺寸、计算样式、祖先链（`tools/probes/`） |
| `capturePage()` 截图 | 比外部截图工具可靠（本机 GDI `bmp.Save` 会抛异常，别依赖它） |
| profile 隔离 | 探针用独立的 `userData` 目录（`.electron-scratch*`），不干扰正在使用的客户端；想知道真实状态就指定同一个 profile |
| 重启客户端 | 普通启动会被自动化会话最小化，改用计划任务：`Register-ScheduledTask -Execute <exe> -LogonType Interactive` → `Start-ScheduledTask` |
| 插件改动 | 改完 `node --check` 校验，再刷新客户端即可（`link:` 安装，无需重装） |

## 八、故障排查

| 现象 | 先查这里 |
| --- | --- |
| 插件没生效 | profile 的 `bundles` 里有没有它；`dependencies` 是否 `link:` 到位 |
| 白屏 | 插件的 `peerDependencies` 有没有 `react`；`inject` 有没有漏声明 |
| 侧栏宽度不记忆 | `dsh-harness-site:panel-width` 是否被写；面板是否处于收起状态启动（DOM 未挂载） |
| 卡片消失 | 检查最近是否用"按尺寸猜元素"的方式写 CSS（会误伤公共类名，本仓库曾因此丢掉两张卡片） |
| 第二次打不开 | 上次的 `dsh` 进程还占着端口 → 壳会自动清理，也可手动 `taskkill` |
